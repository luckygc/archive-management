# GB/T 13967—2026《全宗管理规则》分析

## 调研结论

用户所说的“最新的全宗规范”高度确定是 **GB/T 13967—2026《全宗管理规则》**，而不是仍然现行、但发布于 2012 年的 DA/T 12—2012《全宗卷规范》或 DA/T 14—2012《全宗指南编制规范》。依据如下：

- 国家档案局将 GB/T 13967—2026 列为最新发布的全宗主题国家标准，名称直接由旧版《全宗单》改为《全宗管理规则》；
- 国家档案局专门发布消息，将其称为“新修订的国家标准”，并说明其替代 GB/T 13967—2008《全宗单》；
- 全国标准信息公共服务平台和国家标准全文公开系统均已登记该标准，并提供正式电子文本。

本页依据截至 **2026 年 8 月 11 日** 可获得的一手资料整理。它是标准研究和产品影响分析，不是当前实现合同；本轮采纳的业务规则已经校准到稳定 OpenSpec 并实施，后续仍以对应稳定规格为准。

## 这次修订的性质

这不是对旧《全宗单》栏目做小修补，而是标准对象和管理范围发生了根本变化：

```text
GB/T 13967—2008《全宗单》
└─ 重点：档案馆如何用一张登记单反映全宗管理状况

GB/T 13967—2026《全宗管理规则》
├─ 全宗设置、类型和特殊形式
├─ 立档单位的全宗管理
├─ 档案馆内的全宗管理
├─ 全宗号、全宗属类和动态登记
├─ 全宗卷、全宗介绍、全宗指南
└─ 机构改革、资产与产权变动中的全宗处置
```

国家档案局对新标准的官方解读将其概括为：适用主体从主要面向各级各类档案馆扩展至机关、团体、企业事业单位和其他组织，全宗管理从相对静态的统计登记转向动态、系统的全过程规范。参见[国家档案局《国家标准〈全宗管理规则〉发布》](https://www.saac.gov.cn/daj/szda/202604/870c50b55f5349049f8907a507ce59b7.shtml)。

标准前言明确列出的主要技术变化如下：

| 变化 | 新版位置 | 含义 |
| --- | --- | --- |
| 更改适用范围 | 第 1 章 | 从“全宗单”编制扩展为基于全宗方式的档案管理 |
| 删除旧版全宗单填写章节 | 旧版第 4～6 章 | 全宗单从标准主体退到全过程管理中的一种工具，样式移入资料性附录 B |
| 增加四项基本原则和十项主要工作任务 | 第 4、5 章 | 全宗成为收集、整理、保管、利用、移交和变动处置的核心单元 |
| 增加全宗类型和特殊形式 | 第 6 章 | 明确机构全宗、主题全宗，以及联合全宗、汇集全宗 |
| 增加立档单位的全宗管理 | 第 7 章 | 不再只有档案馆侧登记，立档单位也承担设置、维护、移交和变动处置责任 |
| 增加档案馆内的管理规则 | 第 8 章 | 明确全宗属类、全宗号、全宗卷、全宗指南、全宗单和应用系统能力 |
| 增加机构改革、资产与产权变动处置 | 第 9 章 | 明确新设、沿用、终止、封闭和交接等生命周期动作 |

上述比较来自[标准正式电子文本](https://openstd.samr.gov.cn/bzgk/std/newGbInfo?hcno=4E4E47996009F8540337E489F2C5640E)前言，不依赖二手解读。

## 正文关键规则

### 1. 全宗不再只等于“一个当前机构”

标准第 3.1 条把全宗范围扩展为两类具有内在联系的档案整体：一类来自同一组织，另一类围绕特定主题进行管理。第 3.3、3.4 条进一步区分：

- **机构全宗**：同一组织形成的档案整体；
- **主题全宗**：围绕知名人物、文化产业、重大活动、突发事件等特定主题，内容系统全面的档案整体。

第 6.1.1 条给出机构成为立档单位的三个判断维度：独立行使职权并以本单位名义开展活动、预算或财务独立、具有一定人事任免权；特殊情况下，以第一项作为最基本标志和主要条件。

第 6.2 条允许档案馆建设主题全宗，但设置前应明确目标和计划，避免低效、过滥设置；立档单位一般不设置主题全宗。第 6.2.4 条还明确，不应为了突出主题而抽取其他全宗内档案，破坏原全宗构成。

### 2. 联合全宗、汇集全宗是特殊形式，不宜只用普通“父子全宗”表达

第 6.3 条区分：

- **联合全宗**：两个或以上立档单位的文件运转、行政事务统一，形成单位难以区分时，作为一个机构全宗的特殊形式；
- **汇集全宗**：多个数量小、具有共同特征或联系的全宗，为提高管理效率而汇集管理；
- **档案汇集**：对无法明确归宗或归属已不存在的零散文件采用的补充性管理形式，参照汇集全宗管理，但概念上不等同于常规全宗。

因此，系统需要区分“全宗类型”“特殊形式”和“全宗之间的历史关系”，不能仅靠一个通用树形 `parent_id` 混合表达。

### 3. 四项原则会转化为系统不变量

第 4 章确立：

- **尊重来源**：档案与形成者之间的关系应保留；
- **完整有机**：同一全宗的不同门类、不同载体统一管理，不同全宗归属明确；
- **系统关联**：全宗管理与收集整理、保管保护、移交接收关联，并动态维护全宗卷、全宗介绍和全宗单；
- **稳定延续**：全宗结构和核心管理规则保持稳定，机构或产权变动时规范处置并延续管理过程。

系统层面的直接含义是：跨全宗移动、拆分、合并、改号、终止都不应是普通编辑操作；必须有明确业务动作、权限、原因、依据、前后状态和审计记录。

### 4. 全宗号由档案馆分配，且要保持系统性和持续性

第 7.1 条规定：属于档案馆接收范围的，全宗号由档案馆统一赋予，立档单位不应自行变更；不属于接收范围的，可以不设置，或由单位结合实际拟定。

第 8.3 条规定档案馆制定分配方案，全宗号按照 DA/T 13 确定，一般由“全宗属类代码 + 3 位数字”组成。合并时应根据延续性决定沿用某一原全宗号或重新确定全宗号，并尽量保持系统性、持续性。

这意味着系统不能把“全宗号”视为一个始终可自由改写、可删除后复用的普通名称字段；还需要区分数据库身份、业务全宗号、分配状态和分配机关。

### 5. 立档单位与档案馆承担不同职责

第 7 章面向立档单位，核心要求包括：

- 制定全宗管理制度、档案分类方案、归档范围和保管期限表；
- 按 DA/T 12 编制全宗卷；
- 宜在数字档案室应用系统中支持全宗信息配置与编辑；
- 移交时同步提供全宗介绍、大事记、机构沿革等背景材料；
- 机构变动时按经同意的处置方案处理，终止的全宗调整为“封闭全宗”。

第 8 章面向档案馆，核心要求包括：

- 设置全宗属类并按全宗制订接收计划；
- 审核申请材料、赋予全宗号；
- 编制和动态修订全宗指南；
- 建立、补充全宗卷；
- 动态维护全宗单；
- 宜在数字档案馆应用系统中支持全宗号分配、全宗调整记录、全宗卷管理等功能。

因此，“档案室系统”和“档案馆系统”不能简单共用一套无角色差异的全宗 CRUD；最少要通过部署定位、机构能力或权限边界区分职责。

### 6. 全宗卷、全宗介绍、全宗指南和全宗单是四类不同对象

| 对象 | 主要责任方 | 新标准要求 | 系统特征 |
| --- | --- | --- | --- |
| 全宗卷 | 立档单位、档案馆 | 第 7.4、8.6 条；按 DA/T 12 管理，档案馆侧还会持续补充长期管理记录 | 文档集合，分类组织，持续追加，需版本与审计 |
| 全宗介绍 | 立档单位 | 第 7.5 条；说明单位性质、职能、机构、档案构成、开放审核等 | 移交背景材料，应可版本化 |
| 全宗指南 | 档案馆 | 第 8.5 条、附录 A；包含来源简况、内容与成分、检索查阅注意事项，并标注编制人、时间，动态修订 | 面向利用者的段落式检索工具，不等同于全宗备注 |
| 全宗单 | 档案馆 | 第 8.7 条、附录 B；宜用电子表单动态维护，可扩展栏目 | 汇总登记与统计视图，不应成为唯一事实来源 |

附录 B 给出的全宗单基础栏目为：序号、全宗号、全宗名称、全宗属类、起止时间、档案数量、存放位置、演变关联情况、备注。档案数量还可按门类、统计单位细化。

### 7. 机构改革和产权变动需要事件化处理

第 9 章按场景给出处理原则：

| 变动场景 | 全宗处置摘要 |
| --- | --- |
| 多单位撤销合并为新单位 | 原单位各自封闭；新单位原则上建立新全宗 |
| 以某原单位为主体吸收其他单位 | 主体全宗延续；其他被撤销单位原全宗封闭 |
| 撤销后恢复且主要职能未重大变化 | 沿用原全宗 |
| 内设机构划出成为新单位 | 成立后建立新全宗；之前档案仍属原全宗 |
| 独立单位变为另一单位内设机构 | 变更前全宗封闭；之后档案进入新单位全宗 |
| 内设机构划转 | 划转前后档案分别属于原单位和接收单位全宗 |
| 名称、隶属、内设机构等变化但基本职能未根本变化 | 可沿用原全宗，并在全宗介绍中说明 |
| 企业资产与产权变动 | 按监督指导关系报告，结合国企档案归属流向规则处理 |

标准第 9.5 条还要求档案馆跟踪记录档案处置和全宗调整情况。这适合建模为“变动事件 + 处置决定 + 关系 + 证据材料”，而不是覆盖原全宗的名称、组织 ID 或状态。

## 对当前项目的影响

### 已完成对齐的基础

当前项目有几项基础判断与新标准方向一致：

- [CONTEXT.md](../../CONTEXT.md) 已明确全宗不是租户，当前组织不能代替全宗；
- [archive-metadata 规格](../../openspec/specs/archive-metadata/spec.md) 已把全宗作为档案归属维度，并与档案分类分开；
- 档案记录、检索、运行时规则和全宗可用分类均显式携带全宗作用域；
- 当前模型使用独立数据库主键和不可变 `fonds_code` 作为系统身份，不再把它展示或解释为业务全宗号；
- 可空 `fonds_no` 单独表达业务全宗号，使用专用动作登记且登记后不可普通修改；
- 全宗分类范围、案卷、档案条目、接收包和运行时规则中的全宗编码均有数据库外键约束；
- 全宗使用 `ACTIVE`、`CLOSED` 生命周期，不再通过启用开关或逻辑删除表达封闭；
- 号码登记、封闭和恢复形成只追加事件，正式归档条目的跨全宗变化使用专用动作并写操作审计。

这些基础应保留，不需要因为新标准改回“组织即全宗”或“全宗只是档案分类字段”。

### 当前产品的适用边界

[PRODUCT.md](../../PRODUCT.md) 已把 archive-management 定位为**面向机构内部使用**的档案管理系统，不是档案馆综合管理平台。因此，新标准各章对当前项目的影响应分层判断：

| 标准内容 | 责任主体 | 对当前产品的判断 |
| --- | --- | --- |
| 第 4～6 章：原则、任务、全宗设置 | 各类档案机构 | 作为领域不变量和概念依据，但机构内部产品一般以机构全宗为主，不因标准出现主题/联合/汇集概念就立即实现所有类型 |
| 第 7 章：立档单位的全宗管理 | 机关、团体、企业事业单位和其他组织 | **当前直接边界**，重点关注全宗号来源、管理制度、全宗卷、移交背景材料和封闭全宗 |
| 第 8 章：档案馆内的全宗管理 | 档案馆 | **当前条件性边界**；全宗属类、全宗号申请分配、全宗指南、全宗单、接收计划不是当前产品当然必做项 |
| 第 9 章：机构改革、资产与产权变动 | 主管部门、立档单位、档案馆 | 当前需要保存本机构的处置依据、历史归属和封闭/延续结果，但软件不能替代主管部门作专业决定 |

这一区分也解释了两个容易混淆的词：

1. 第 7.3 条的“档案分类方案”是立档单位制定并执行的业务制度或文件，不等于项目此前删除的结构化“分类方案”配置实体。当前[档案分类稳定规格](../../openspec/specs/archive-classification-scheme/spec.md)无需回退；系统运行时仍可采用全局分类树和全宗显式可用分类，正式分类方案则可在全宗卷中按版本保存。
2. 第 8.1 条的“全宗属类”是档案馆对馆藏全宗按历史时期、机构性质、机构级别、主题等做的属性分类，不是当前 `am_archive_fonds_category_scope` 所表达的“某全宗可使用哪些档案分类”。当前产品没有档案馆属类管理需求时，不应为了术语相似复用或改造这张关系表。

### 本轮实施结果与剩余边界

本轮直接重构原型基线，已经消除“系统身份与业务全宗号混用”这一首要风险，而没有增加兼容字段或后置增量迁移：

| 能力 | 当前实现 | 后续边界 |
| --- | --- | --- |
| 稳定身份与可选业务全宗号 | `fonds_code` 为全局唯一、不可修改且不可复用的系统编码；`fonds_no` 可空、全局唯一，并通过 `:assignNumber` 登记分配机关、时间和原因 | 全宗号申请、审核和分配工作流属于档案馆场景，当前不实现 |
| 生命周期状态 | 全宗只有 `ACTIVE`、`CLOSED`；`:close`、`:reopen` 保存生效时间和原因，封闭后仍可查询历史但不能作为新增、导入或调整归属的目标 | 机构合并、撤销恢复、划转和延续仍需独立业务事件与处置证据 |
| 引用完整性 | 全宗分类范围、案卷、条目、接收包和运行时规则的 `fonds_code` 均引用全宗主数据 | 权限数据范围当前按字符串规则表达，由服务校验其全宗语义 |
| 全宗事件 | 号码登记、封闭、恢复写入不可更新、不可删除的事件表 | 后续真实需求出现时再增加合并、划转、延续等事件类型 |
| 形成者与历史背景 | 已有全宗名称、起止日期和机构沿革说明 | 形成者实体、规范名称、处置依据及背景材料版本尚未建模 |
| 正式档案跨全宗调整 | 未正式归档条目可在普通编辑中纠正；正式归档条目必须调用 `:reassignFonds`，通过权限、数据范围、分类范围、锁定和案卷校验后写 `REASSIGN_FONDS` 审计 | 涉及机构整体处置时不能用逐条调整替代专业处置流程 |
| 全宗卷与治理文件 | 尚未表达 | 按真实交付需要复用文件存储和审计能力，依 DA/T 12 组织全宗卷并版本化治理文件 |
| 全宗类型和特殊形式 | 尚未表达 | 机构内部场景继续以机构全宗为主；主题、联合、汇集全宗只在真实场景出现时扩展 |

全宗管理页面和 API 已同步采用上述语义：创建与基本信息编辑不接受业务全宗号，号码登记、封闭、恢复均为显式动作，事件单独查询；不再提供启用切换或删除入口。

主题全宗、联合全宗、汇集全宗仍可作为未来真实场景出现时的模型扩展点，但不因标准列出概念就提前增加空洞的类型、页面和工作流。

### 第 8 章馆侧能力的条件性影响

如果未来产品定位扩展到档案馆，才需要另开 change 评估：

- 全宗属类及其代码；
- 全宗号申请材料、审核和分配；
- 按全宗制订接收计划；
- 档案馆编制和动态修订的全宗指南；
- 档案馆长期补充的全宗卷；
- 全宗单电子表单及按门类、统计单位细化的数量；
- 全宗号分配、全宗调整记录等馆侧应用能力。

届时“全宗单”宜作为汇总读模型或可追溯快照，从主数据、档案统计、位置和变动事件投影生成，而不是把所有事实重复手填在一张孤立表里。新版删除旧版纸面全宗单的固定填写章节，不等于取消全宗单，也不意味着旧的收进、移出、结存等历史统计明细应被丢弃；这些明细更适合保留在统计或事件台账中，再投影到新版宏观表。

## 最终判断

GB/T 13967—2026 对档案管理系统最重要的影响，不是“多加几个全宗字段”，而是把全宗从低频配置项提升为**稳定的来源与历史连续性边界**：

> 全宗管理从一张静态登记表扩展为设置、收集、整理、保管、利用、移交和机构变动处置的全过程管理，并要求持续维护相关背景、文档和调整记录。

当前项目已经在机构内部产品边界内完成第一阶段对齐：**稳定系统身份与可选业务全宗号已经拆分，`fonds_code` 引用已受约束，封闭生命周期与只追加事件已经建立，正式归档后的跨全宗变化也已收敛为受控动作**。全宗卷、形成者背景和机构整体变动处置按第 7、9 章随真实场景补齐；全宗属类、分号工作流、全宗指南、全宗单等第 8 章馆侧能力暂不进入当前必做范围。
