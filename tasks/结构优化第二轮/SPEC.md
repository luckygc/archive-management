# 第二轮结构与恢复能力优化

## 目标与范围

实现当前审查确认的八项优化，保持既有 API、权限、状态机、事务和原子写入边界，不新增依赖或开发常驻服务。

## 验收要求

1. 允许排序的隐藏动态字段参与内部投影和游标取键，响应仍只包含可见动态字段。可空、多列排序在 PostgreSQL 中按升序空值最后、降序空值最前执行，下一页和上一页遍历无重复、无遗漏；签名游标保留空键位置。
2. 卷创建规则使用创建候选，卷已有数据的加条目规则使用实际密级、保管期限。规则输入使用有业务语义的命令对象，保留阻断、锁定、权限和事务语义。
3. 关联创建与删除互斥；规则编辑目录加载只应用当前编辑上下文响应；全宗筛选列表在状态变化后与筛选条件一致。加载错误可见并可重试，过期响应不能覆盖新状态或清除新请求的忙状态。
4. 导入预检与正常写入共用字段值转换，保留逐行错误、字段名与全批次零写入语义，复用列名映射。
5. 用户角色读取与导出规则事实读取使用批量查询，保留关系顺序、缺失数据、停用角色与每个实际全宗/分类规则执行语义。
6. 档案管理与查阅共用查询恢复状态实现，保留各自端点和业务边界、查询草稿与已提交请求、游标失效回首页、追踪标识及重复重试防护。
7. archive 内部子域不跨界直接访问 Repository；共享动态 Mapper 调用方明确且由 ArchUnit 固化。元数据写入的规则引用保护仍有效，元数据只读目录 Bean 不反向依赖规则。
8. 完整验证在 Docker 不可用、容器集成测试缺失/跳过或前端无测试时失败；GitHub Actions 复用同一真实验证入口，不增加部署动作。

## 验证

真实入口以根目录 mise.toml、server/pom.xml 和 frontend/package.json 为准。缺陷采用可控异步回归、真实 PostgreSQL 分页/规则测试和单次批量调用验证，最终执行完整 verify。远端 CI 只有推送后实际运行才能确认结果。
