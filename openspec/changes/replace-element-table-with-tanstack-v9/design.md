## Context

管理端现有约三十个业务表格由各页面直接声明 `el-table` 和 `el-table-column`。大多数表格展示完整的内存集合，部分表格展示 cursor 分页结果；档案检索接口已经接受有顺序的 `orderBy` 数组，但 Element Plus 的 `sort-change` 事件只保留一个活动列。此次变更跨越共享 UI、二十余个页面和关键交互测试，同时引入新的 MIT 依赖，因此需要先固定统一的状态和迁移边界。

## Goals / Non-Goals

**Goals:**

- 由共享组件集中 TanStack Table v9 的列、排序、行模型和语义化 HTML 渲染。
- 所有管理端业务数据表格停止直接使用 Element Plus 表格组件。
- 本地完整集合提供稳定的多列排序；远程列表只在服务端合同支持时提交完整排序状态。
- 保留现有表格的加载、空状态、操作单元格、树形层级、当前行选择、固定操作列和横向滚动能力。
- 用排序优先级、方向图标、可访问名称和操作提示提高多列排序的可发现性。

**Non-Goals:**

- 不扩展没有 `orderBy` 合同的后端列表接口。
- 不实现虚拟化、列拖拽、列宽拖动、行内编辑或新的数据获取层。
- 不替换 Element Plus 的非表格组件，也不追求逐像素复刻其表格 DOM。

## Decisions

### 使用稳定版 TanStack Table v9 的无头能力

共享组件直接使用 `@tanstack/vue-table` v9 的列模型、排序 feature 和行模型，以项目原生 HTML/CSS 渲染表格。这样排序状态不再依赖第三方视觉组件事件，列单元格仍能通过 Vue 插槽组合 Element Plus 按钮、标签和开关。

替代方案是继续用 `el-table` 渲染、仅在页面外维护一个多列数组。该方案仍受单列排序事件和表头状态限制，也不能完成用户要求的替换，因此不采用。另一方案是为每个页面直接编写 TanStack 配置，会重复可访问性和样式逻辑，也不采用。

### 共享组件采用列定义加命名插槽

页面传入包含 `key`、`label`、访问器、宽度、排序能力和固定位置的列定义；复杂单元格以 `#cell-<key>` 命名插槽接收 `row`、`value` 和行索引。共享组件负责表头、行、空状态、加载容器、树形缩进和粘性列。

列定义是页面数据语义的显式清单，比模拟 `el-table-column` 子组件注册行为更容易进行类型检查和测试。迁移时保留现有业务按钮和文案，不把业务操作下沉到基础组件。

### 区分本地排序与远程排序

默认的 `client` 模式只用于当前 `data` 是完整集合的页面，注册 TanStack 的排序行模型。`manual` 模式不重排传入数据，只通过 `sorting-change` 发送有顺序的 `{ id, desc }[]`，由页面清空旧 cursor 并重新查询。`none` 模式用于服务端分页但没有排序合同的表格，表头不呈现可排序 affordance。

这避免了对当前页排序却让用户误以为已排序全集的失败语义。替代方案是给所有表格默认启用本地排序，代码更少但会破坏分页一致性，因此不采用。

### 多列排序使用组合键并显示优先级

普通点击替换主排序；Shift、Ctrl 或 Command 加点击追加/切换一个排序列。已排序表头显示升降方向，多列时显示从 1 开始的优先级徽标；表头的 `title` 和可访问名称说明下一步动作及组合键。排序状态变化后保持页面现有焦点，不自动滚动。

### 树形数据在共享组件中展开为可见行

共享组件读取列定义之外的 `children` 访问器，以显式展开状态生成可见层级，并在首个数据列渲染展开按钮和缩进。该能力只覆盖现有组织部门表的树形展示，不引入通用分组或懒加载协议。

## Risks / Trade-offs

- [TanStack v9 API 与 v8 不兼容] → 固定使用 v9 的 `useTable`、显式 feature 注册方式，并通过类型检查和组件测试锁定集成面。
- [一次性迁移页面较多，可能遗漏表格行为] → 先完成共享组件测试，再按使用清单逐页迁移，最后以源码扫描禁止残留 `el-table`。
- [原生表格与 Element Plus 视觉存在差异] → 复用 `DESIGN.md` 的颜色、间距、圆角和阴影变量，只保证项目设计语言与信息密度，不复制内部类名。
- [粘性操作列在窄屏遮挡内容] → 表格容器始终允许横向滚动，固定列带分隔阴影，页面可对非必要列设置最小宽度。
- [本地排序可能改变服务端默认顺序] → 仅在用户主动点击后排序；初始状态保持传入顺序。
- [远程排序请求失败] → 页面保留最新已提交结果并显示既有错误反馈；新排序再次提交时清空旧 cursor，防止 token 与查询摘要不一致。

## Migration Plan

1. 在前端 catalog 和管理端包中加入稳定版 `@tanstack/vue-table` v9。
2. 新增共享表格类型、组件、样式和测试，覆盖本地多列排序、远程排序事件、空状态、树形行及可访问表头。
3. 先迁移档案检索表并接通既有 `orderBy` 数组，再迁移其余完整集合和分页列表。
4. 更新页面测试及自动生成的组件声明，执行源码扫描、前端检查、测试和治理检查。
5. 如需回滚，恢复页面的 `el-table` 声明并移除共享组件与依赖；没有数据库或 API 迁移需要回退。

## Open Questions

无。后续若某个分页接口需要用户排序，应在对应业务规格中明确字段白名单和稳定排序后，再把该页面从 `none` 切换为 `manual`。
