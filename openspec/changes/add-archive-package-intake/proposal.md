## Why

现有归档接收只有“未配置外部连接”的占位入口，既没有可接收的业务对象，也没有实现 DA/T 93—2022 所要求的检测、交接和入库闭环。标准中的移交对象已经是电子档案，因此系统应先形成可追溯的移交信息包记录，自动检测通过后等待接收人员完成人工复核和交接确认，确认接收后再原子写入正式档案库。

## What Changes

- 增加档案信息包上传、包级接收记录、同步处理状态、失败原因和生成条目关联。
- 以现行 DA/T 93—2022《电子档案移交接收操作规程》为主线定义离线接收格式，支持其附录 B“件”级移交信息包结构；ZIP 仅作为网页上传时对标准目录树的传输封装。
- 长期保存原始 ZIP，并依据 DA/T 70—2018《文书类电子档案检测一般要求》记录真实性、完整性、可用性和安全性的自动检测结果及人工/外部复核项。
- 安全解析 `说明文件.TXT`、`目录文件.XML`、全宗/分类目录、档案元数据 XML 和内容数据；自动检测通过后进入待复核，不提前生成档案条目。
- 接收人员确认来源固化信息、内容可读、病毒检测、离线载体和线下交接手续后，原子生成位于系统 `HOLDING` 库的正式电子档案；也可记录原因退回。
- 增加接收记录列表与详情 API，并将归档接收页面改造成可上传、查看处理结果和失败原因的工作台。
- 保留 `GET /api/v1/intake` 概览，更新其说明以反映本地信息包接收能力。
- 目标：完成“上传离线移交信息包 → 原包留存 → 自动检测 → 人工复核与交接确认 → 接收并入正式库或退回 → 查看检测与交接结果”的闭环。
- 非目标：正式入库审批、NAS/SFTP/HTTP 等在线连接、DA/T 48—2009 EEP 封装包、电子签名验签、内置杀毒引擎、离线载体物理外观/读取速度检测、自动重试和通用异步任务平台。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `intake`：将归档接收从占位入口扩展为电子档案移交信息包接收、自动检测、人工复核、交接确认、正式入库或退回和结果查询能力。

## Impact

- 真相源：修改 `openspec/specs/intake/spec.md` 的增量合同，并遵循 `openspec/specs/api-contract/spec.md`。
- 后端：归档接收 Controller、Service、流式 ZIP 解析、对象存储与事务补偿协作、固定接收记录实体/Repository、Flyway 迁移及测试。
- 档案核心：复用档案分类、全宗、权限、正式档案库和档案条目创建边界，补充按编码/名称/角色解析所需的窄服务方法。
- 前端：归档接收页面、API client、类型与页面测试。
- 依赖：复用 JAXP、Java ZIP、Jakarta Data、现有 Vue 3 与 Element Plus，不新增第三方依赖。
